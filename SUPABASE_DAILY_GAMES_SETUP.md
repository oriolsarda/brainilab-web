# Content pools

## BrainiWord

Initial seed:

```text
130 five-letter words
```

Words stay in PostgreSQL.

The initial page payload does not receive the answer.

For each guess the page calls:

```text
check_brainilab_brainiword_guess(...)
```

and receives only the letter states:

```text
correct
present
absent
```

The answer is returned only when the puzzle is won or the fifth attempt is used.

The generator attempts to avoid reusing a BrainiWord answer for 60 days.

## Flag Dash

Initial country pool:

```text
79 countries
```

Each Daily selects:

```text
30 countries
```

and generates four answer options for every flag.

The client receives:

```text
ISO country code
option IDs
option names
```

The flag emoji is generated from the ISO code in the browser.

It does not receive the correct country ID as a dedicated answer field.

## Map Hunt

Initial seed:

```text
60 geography clues
```

Each Daily selects:

```text
10 clues
```

with four country options per clue.

Examples include landmarks, cities, geography and well-known locations.

# Verification

Step 7 adds:

```text
verify_brainilab_flagdash_result(...)
verify_brainilab_maphunt_result(...)
verify_brainilab_brainiword_result(...)
```

PostgreSQL recalculates the result from the exact Daily content.

For Flag Dash it recalculates:

```text
correct
accuracy
best combo
score
```

For Map Hunt:

```text
correct
accuracy
score
```

For BrainiWord:

```text
won
attempts
```

The result is marked:

```text
answers_verified = true
```

`server_verified` remains `false`.

That distinction is intentional. The public answer-check RPC can still theoretically be scripted outside the normal UI, so this step verifies content/result consistency but does not yet claim full anti-cheat competitive integrity.

Before high-stakes global rankings, answer attempts should be sessionized server-side.

After Step 7 finishes:

```sql
select
  dc.challenge_date,
  dc.daily_number,
  (
    select count(*)
    from public.daily_brainiword w
    where w.daily_challenge_id=dc.id

    from public.daily_flag_dash_questions f

    where m.daily_challenge_id=dc.id

from public.daily_challenges dc
order by dc.challenge_date;
```

Every Daily should show:

```text

flags      = 30
map_clues  = 10
```

If Step 5 currently has 15 generated Daily rows, all 15 should already have these values after the migration.

# Frontend resilience

If Supabase is temporarily unavailable:

- Flag Dash has a deterministic local fallback.
- Map Hunt has a deterministic local fallback.
- BrainiWord has a deterministic local fallback.

Fallback results remain local / non-cloud-verified until a proper cloud Daily can be used.

This prevents the Daily product from becoming blank due to a temporary content request problem.
